# Legal AI Judiciary — End-to-End Project

A from-scratch reference implementation of a Legal AI system for legal-document analysis and similar-case retrieval.

## Architecture

React/Vite → FastAPI → MongoDB
                         ├── PDF extraction
                         ├── case/sub-case detection
                         ├── Hybrid Legal NER (InLegalBERT + BiLSTM + CRF)
                         └── Sentence-Transformer case similarity

## Important

This repository is intentionally built so the **training architecture and inference architecture match**. Large datasets and model checkpoints are downloaded/generated by scripts rather than embedded in this ZIP.

## 1. Backend

```powershell
cd backend
python -m venv venv
venv\Scripts\activate
pip install -r requirements.txt
copy .env.example .env
```

Start MongoDB, then:

```powershell
python -m uvicorn app.main:app --reload --port 8000
```

API: http://127.0.0.1:8000
Docs: http://127.0.0.1:8000/docs

## 2. Frontend

```powershell
cd frontend
npm install
npm run dev
```

Frontend: http://localhost:5173

## 3. Create demo legal data

```powershell
cd backend
python scripts/create_demo_cases.py
python scripts/build_embeddings.py
```

The demo data is deliberately small so the application works immediately.

## 4. Hybrid NER training

The training pipeline expects a token-classification JSONL dataset at:

`backend/data/raw/ner.jsonl`

Each line:

```json
{"tokens":["The","High","Court"],"ner_tags":["O","B-COURT","I-COURT"]}
```

Run:

```powershell
python scripts/train_hybrid_ner.py --data data/raw/ner.jsonl --epochs 1
```

The resulting checkpoint is saved under `backend/models/legal_ner/`.

Evaluate:

```powershell
python scripts/evaluate_hybrid_ner.py
```

## 5. Production dataset

Replace the demo case file with a legally licensed/public dataset appropriate to your project. The application accepts normalized records with:

- case_id
- title
- case_type
- sub_case_type
- summary
- facts
- judgment

Then rebuild embeddings.
